# 结构化幻灯片 Markdown 规范

这份规范用于把知识文本整理成厦与珈可以直接导入的 Markdown。AI 先读这份规范，再读一份或多份知识文本，最后只输出一份符合本规范的 Markdown。厦与珈在本地读取这份 Markdown，严格校验后新建项目，不联网，不猜测缺失字段。

## 一、输出要求

1. 只输出一份 Markdown 文件，不输出解释、前言、后记或代码围栏。
2. 使用下面的 YAML 头、章节标题、页面标题和 `:::` 内容块。
3. 全部字段必须写全。缺少必填字段、出现未知字段、指令没有闭合、缩进超过两级，导入都会报错并指出行号。
4. 不要写封面页和目录页。厦与珈根据 YAML 头自动生成封面和目录。
5. 不要手写“图 1”“表 1”或页码。编号由厦与珈生成。不要写结尾页，结尾页由厦与珈根据 YAML 头自动生成。
6. 不要写 Markdown 链接、裸网址、HTML、代码围栏或 data URL。需要交代来源时写成普通中文句子。
7. 图片只能引用本地文件，路径相对于这份 Markdown 所在目录，只能是 png、jpg 或 jpeg。
8. 正文使用中文。每一页只讲一个概念，页面标题控制在 18 个汉字以内，组标题控制在 16 个汉字以内。要点正文不设固定字数上限，按内容需要写完整。一页可以写多组要点。
9. 文风遵守以下规则。不使用直角引号，不使用“代价”一词，正文不使用全角冒号和全角分号，不使用“基线”“缺口”“研究空白”“填补空白”等模板词，每句写完整主谓宾。
10. 正文自动标注重点。AI 主动判断这一页的核心判断和关键术语，用 `**...**` 标出，不要等待原文自带标记。每页 1 到 3 处，规则见“自动重点标注”。

## 二、文件结构

一份文件依次包含四层：

1. YAML 头，写项目、主题和封面信息。
2. 一级标题，表示章节。
3. 二级标题，表示页面，标题末尾必须写版面。
4. `:::` 内容块，表示这一页的文字、要点、图片或表格。

文件里不能有这四层之外的内容。空行可以保留。内容块必须写在页面标题下面，页面必须写在章节标题下面。

## 三、YAML 头

文件第一行必须是单独的 `---`，YAML 结束后再用单独的 `---` 收尾。

```yaml
---
format: xyj-deck/v1
project:
  name: 分类问题示例
  theme: whu
  showDots: true
cover:
  title: 分类问题示例
  fields:
    - label: 主讲人
      value: 张三
      size: lg
      showLabel: true
      role: presenter
    - label: 单位
      value: 武汉大学新闻与传播学院
      size: md
      showLabel: false
    - label: 日期
      value: 2026 年 11 月 23 日
      size: md
      showLabel: false
ending:
  title: 恳请各位批判指正
---
```

字段说明：

- `format` 必须是 `xyj-deck/v1`。
- `project.name` 是项目名，不能为空。
- `project.theme` 只能是 `whu`、`whu-lake`、`whu-tile`、`whu-vine`、`whu-gold`、`whu-mist`、`xmu`。
- `project.showDots` 是页面导航圆点，写 `true` 或 `false`。
- `cover.title` 是封面标题，不能为空。
- `cover.fields` 至少一项。每项必须有 `label`、`value`、`size`、`showLabel`。
- `size` 只能是 `lg`、`md`、`sm`。
- `role` 可以省略；如果写，只能是 `presenter`。整份文件必须恰好有一个 `role: presenter`。
- `ending` 可以省略。`ending.title` 是结尾页的中间文字，省略时默认“恳请各位批判指正”。
- 结尾页的汇报人取自封面 `role: presenter` 的字段，汇报时间取自封面的日期字段。不要写结尾页的内容块，结尾页由厦与珈生成。

## 四、章节和页面

章节用一级标题，页面用二级标题。页面标题末尾必须用 `{layout=...}` 指定版面。

```markdown
# 分类问题的表示

## 从数字编码到独热向量 {layout=full}
```

版面只有四种：

- `full` 是整页，默认用法。
- `rows` 是上下两版，均为平分。
- `cols` 是左右两版，均为平分。
- `grid` 是上下左右四分版，均为平分。

页面标题的写法必须是 `## 标题 {layout=full}` 这种形式。缺少 `{layout=...}`、写错版面名、或者使用三级标题都会报错。章节标题不写版面。

页面标题不必每一页都不同。连续几页讲同一个问题，可以共用一个页面标题，不需要为了每页不同而另起标题。

## 五、内容块

内容块以 `:::` 加类型开始，以单独的 `:::` 结束。内容块不能嵌套。每页至少有一个内容块。

类型只有十种：

- `definition` 定义
- `theorem` 定理
- `consensus` 共识
- `group` 编组
- `bullets` 要点
- `figure` 图片
- `table` 表格
- `code` 代码
- `references` 文献
- `footnote` 脚注

内容块开头的属性写成 `key=value`，有空格的值必须用双引号包住。属性不能重复，不能写当前类型不支持的属性。

所有内容块都可以写 `centered=true`。这个选项只在这个版面只有一个内容块时生效，让它在版面里垂直居中。默认不写，保持原来的顶部对齐。它不改变字体和字号。规范不强制使用，按版面需要决定。

### 1. 定义、定理、共识、编组

```markdown
::: definition
分类是从特征空间到离散标签空间的映射。
:::
```

可选属性：

- `label="..."` 改块标题。省略时使用“定义”“定理”“共识”“编组”。
- `align=left|center` 控制整块正文对齐，默认左对齐。
- `pane=0|1|2|3` 分版时写所属版面；整页可以不写。

正文可以有多行，空行保留。正文不能为空。

### 2. 要点和辅助说明

一个 `::: bullets` 内容块是一组要点。每组可以写一个组标题，组标题写在 `::: bullets` 的 `title` 属性里。组标题下面可以有多条要点。一页可以写多个 `::: bullets` 内容块，纵向排列。组标题可以省略，省略后组内要点直接排列。

```markdown
::: bullets title="数字编码不适合作标签"
- 数字编码把类别写成 1、2、3
  - 这种写法默认类别之间存在数值距离
- 分类问题不应假设类别有大小关系
:::

::: bullets title="独热向量消除数值距离"
- 每个类别放在独立维度
  - 每一维只取 0 或 1
:::
```

规则：

- 组标题可以省略。是否写组标题由 AI 判断。这一组有共同判断就写，只是几条并列事实、没有共同判断就省略。
- 写的时候不超过 16 个汉字，概括这一组要点的共同判断。不要只写话题，不要写口语化的整句。
- 要点行以 `- ` 开头，顶格写。一个圆圈代表一条要点，圆圈右边是这条要点的正文。
- 要点正文不设字数上限，按内容需要写完整。
- 圆点对齐要点正文的第一行，不能落在两行之间。
- 组标题本身已经是加粗的重点样式，标题里不要再写 `**`。行内重点写在正文里。
- 辅助说明行以两个空格加 `- ` 开头，只能两层。
- 不允许第三层缩进，不允许用制表符缩进。
- 一条辅助说明写一行。多个辅助说明就写多行。
- 辅助说明必须写在某条要点后面，不设字数上限，写完整句子。
- 行末写 `{.center}` 可以把这一行放到页面或版面的中线。默认左对齐。圆点仍在左侧。

```markdown
::: bullets title="对齐示例"
- 这条要点保持左对齐
- 公式行 $d'=z(H)-z(FA)$ {.center}
  - 这条说明默认左对齐
  - 这条说明在版面中居中 {.center}
:::
```

上面的对齐示例只演示格式，组标题不作为内容范例。

### 3. 图片

```markdown
::: figure src="images/roc.jpg" caption="观测点与拟合曲线" pane=0
:::
```

属性：

- `src` 必填，是相对 Markdown 文件的本地图片路径，只能 png、jpg 或 jpeg。
- `caption` 必填，写图片说明，不要写“图 1”。
- `pane` 在分版页面必填，整页页面可以省略。
- `scale` 可选，默认 `1`，必须是大于 0 的数字。

图片内容块不需要正文。图片只在本地读取，http、https、ftp、data URL、绝对路径和 `..` 都会报错。

### 4. 表格

```markdown
::: table caption="四种判断结果" placement=center firstColumnHeader=true
| 实际情况 | 判为真 | 判为假 |
|:---|:---:|:---:|
| 实际为真 | 命中 | 漏报 |
| 实际为假 | 虚警 | 正确拒绝 |
:::
```

属性：

- `caption` 必填，写表注，不要写“表 1”。
- `placement=left|center|right` 是整张表在页面或版面里的位置，默认 `center`。
- `firstColumnHeader=true|false` 表示首列是否为行标题，默认 `false`。
- `pane` 在分版页面必填，整页页面可以省略。
- `scale` 可选，默认 `1`，必须是大于 0 的数字。它只调整表格内边距，不改变字号。

表格体：

- 第一行是表头。
- 第二行是分隔行，必须有至少三个短横线。
- 后面至少有一行数据。
- 每行以 `|` 开始，以 `|` 结束。列数必须一致，最多 12 列。
- 单元格内容里的竖线写成 `\|`。不要在表格单元格里写 `|` 本身。

分隔行的冒号控制这一列的文字对齐：

- `:---` 左对齐
- `:---:` 居中
- `---:` 右对齐
- `---` 居中

表注跟随整张表移动，并在表宽内居中。整表位置只取 `left`、`center`、`right`，不要用空格或缩进控制位置。

### 5. 代码

```markdown
::: code title="Python 示例"
# 读取数据
df = pd.read_csv("data.csv")
# 计算均值
mean = df.mean()
:::
```

属性：

- `title` 可选，写代码块的短标题，不超过 16 个汉字，要概括，不口语化。
- `pane` 在分版页面必填，整页页面可以省略。

正文规则：

- 正文原样作为代码，每行一条，保留缩进和空行。
- 注释按行首符号识别。`#`、`//`、`%`、`--` 开头的行显示为浅灰注释，其余行显示为代码。
- 不要写 Markdown 代码围栏，不要写行内格式标记。代码块里的 `**`、`$` 都按普通字符处理。
- 代码行不能包含单独一行的 `:::`，否则会被当成内容块结束。
- 代码行尽量短，一行放不下就换行或拆页。

### 6. 文献

```markdown
::: references title="参考文献"
- Reif, J., et al. (2025). The effect of AI disclosure on credibility. PNAS, 122(6), e2426766122.
- Iles, I., et al. (2021). The effect of self-affirmation on truth discernment.
:::
```

属性：

- `title` 可选，默认“参考文献”，写块标题。
- `pane` 在分版页面必填，整页页面可以省略。

正文规则：

- 每条文献以 `- ` 开头，一条一行。
- 按 APA 写作者、年份、题名、期刊、卷期和页码。
- 不自动编号，不手写 `[1]`。
- 预览、PDF、PPTX 里使用悬挂缩进，首行顶格，后续行缩进。

### 7. 脚注

```markdown
::: footnote
- 数据来源：作者根据公开报告整理。
- 样本量说明：四项预注册实验合计 4,439 人。
:::
```

规则：

- 脚注内容写在页面底部，自动编号为“注 1”“注 2”。
- 每行以 `- ` 开头，一条脚注一行。
- 每页最多写一个 `footnote` 内容块。
- 脚注字体小，默认浅灰色，不参与正文强调。
- 脚注控制在两条以内，每条尽量一行。放不下就拆页。

## 六、分版和 pane

分版只分正文，页面标题、顶部导航和页脚仍占整页。四个版面都是平分。

版面与 pane 的对应关系：

- `full` 只有 pane 0，可以省略 pane。
- `rows` 的 pane 0 是上版，pane 1 是下版。
- `cols` 的 pane 0 是左版，pane 1 是右版。
- `grid` 的 pane 0 是左上，pane 1 是右上，pane 2 是左下，pane 3 是右下。

分版页面里的每个内容块都必须写 `pane`。整页页面写 `pane=0` 也可以，但通常省略。

图片和文字并排时，图片和文字放进不同 pane。表格和图片不能跨版。字体、字号和行距不因分版改变，只会因为版面变窄而换行。

示例：

```markdown
## 观测点与判别标准 {layout=cols}

::: figure src="images/roc.jpg" caption="观测点与拟合曲线" pane=0
:::

::: bullets pane=1 title="判别标准的两个后果"
- 两个分布的交叠决定判别难度
- 判定标准移动会改变命中率和虚报率
:::
```

## 七、行内格式和数学

行内格式与厦与珈现有编辑器一致：

- `**重点**` 输出为重点色加粗
- `//斜体//` 输出为斜体
- `__下划线__` 输出为下划线
- `~~删除线~~` 输出为删除线
- `^^上划线^^` 输出为上划线
- `==高亮==` 输出为浅色高亮

这些标记由厦与珈在导入时识别，`**...**` 不会显示为星号。

数学公式写在 `$...$` 里，行间公式写在 `$$...$$` 里。不要把中文放进数学公式，不要用 Unicode 箭头、上下标或希腊字母代替公式。例如写 `$1-p$（预测概率）`，不要写 `$1-预测概率$`；写 `$x \to y$`，不要写 `x→y`。

不要写 Markdown 链接。`//` 在厦与珈里表示斜体，不要把它当成网址或注释。

`**...**` 除了列在这里，还要按下一节的规则主动使用。

## 八、自动重点标注

重点由 AI 主动判断并标注，不能只照搬原文的粗体或高亮，也不能整页没有重点。有正文的页面每页标 1 到 3 处。整页只有图片、表格、公式、代码或文献时可以一处不标。

### 1. 标什么

按下面的顺序取，总数不超过 3 处。

1. 核心判断。这一页的结论是听众必须记住的一句话。整条要点就是核心判断时，可以给整条要点加标记，每页最多一条。
2. 关键术语。概念名、方法名、指标名在第一次出现时标注。同一个术语在同一页只标第一次。
3. 对照关系。对比页里构成对照的两个关键词各标一处，例如“命中”和“虚报”。

定义块标关键条件或关键差别。定理块标条件或结论的关键词。共识块标可复述的结论。编组块标共同判断。辅助说明不标重点。

### 2. 怎么标

- 自动标注只用 `**...**`。`==高亮==`、`__下划线__`、`~~删除线~~`、`^^上划线^^`、`//斜体//` 不作为自动重点，避免一页出现多种强调。
- 标记只包住一个词组或一条完整要点，不包住整段、多个相邻词组或整个列表。
- 定义、定理、共识、编组的正文只标关键词组，不标整句。
- 一条要点最多一处标记。同一行不要连续标注两个词。
- 组标题和代码、文献块的标题本身已经是加粗的重点样式，标题里不写 `**`。行内重点写在正文里。
- 页面标题、组标题、块标题、图注、表注、YAML 头和块属性都不写标记。
- 数学公式内部不写标记。公式需要强调时，在公式外的说明文字里标关键词。
- 表格只在确实需要对照的表头或结论单元格里标注，整页仍受 3 处限制。表注不标。
- 标记必须成对闭合，不能跨行，不能嵌套另一种行内标记。

### 3. 例子

一页四条要点，标一条核心判断和一个关键术语。

```markdown
::: bullets title="标签表示决定类别距离"
- **数字编码不适合作为分类标签**
- 数字编码把类别写成 1、2、3
  - 类别之间因此看起来有数值大小和先后
- **独热向量**让每个类别落在自己的维度上
- 类别之间不再有数值远近
:::
```

同一页的错误写法如下。

```markdown
::: bullets title="标签表示决定类别距离"
- **数字编码**把类别写成 **1、2、3**，**类别之间**看起来有 **数值大小**
- 独热向量让每个类别落在自己的维度上
  - **类别之间不再有数值远近**
:::
```

第一行标了四处，超过一页上限，而且把一句话拆成多个相邻标记。第三行给辅助说明加标记。两种写法都会让重点失去层次。

## 九、内容和版面规则

1. 一页只讲一个概念，标题写清这一页的判断或概念。页面标题不必每页都不同，同一问题的连续几页可以共用一个标题。
2. 页面标题不超过 18 个汉字，组标题不超过 16 个汉字。两种标题都要概括对应的判断，写短结论，不写只交代话题的短语，不写口语化的整句，不用“这个”“就是说”“其实”等口头表达。
3. 一页可以写多组要点，按内容自然分组，纵向排列。每组可以写组标题，是否写由 AI 根据这一组有没有共同判断决定。组内每条要点写圆圈加正文，正文不设固定字数上限，辅助说明按需写。
4. 多组要点用多个 `::: bullets` 内容块分开。组标题可写可不写，不写 `###` 小标题。
5. 定义写完整定义，定理写清条件与结论，共识写一句可复述的结论，编组写清这一组内容的共同判断。
6. 要点正文句末不加句号。辅助说明写完整句子，不设字数上限。
7. 长大纲必须拆成多页，并压平成“组标题、要点正文、辅助说明”三层，不能把更深层留给 App 推断。
8. 只有确实需要并排对照时才用左右或上下版。四分版只用于四个独立小点。
9. 一页放不下的内容拆成两页，不缩小字号，也不靠缩小表格字体解决。
10. 不要写封面页、目录页和页码。不要手写图号、表号。
11. 不要写红色。主题色由 YAML 头的 `theme` 决定。
12. 每页正文按“自动重点标注”标 1 到 3 处重点，不标组标题、辅助说明、图注和表注。
13. 一页有图片或表格任意一种时，尽量只搭配一组要点，不要两组。图表占版面，两组要点会挤压。
14. 代码只写在 `::: code` 内容块里，不写 Markdown 代码围栏。注释行以 `#`、`//`、`%`、`--` 开头。
15. 文献按 APA 写，一条一段，不自动编号。脚注放页面底部，每页最多一个 `footnote` 内容块，控制在两条以内。

# 分类问题的表示

## 从数字编码到独热向量 {layout=full}

::: bullets title="数字编码不适合作标签"
- 类别被写成 **1、2、3**
  - 这种写法默认类别之间存在数值距离
- 类别之间因此出现数值大小和先后
:::

::: bullets title="独热向量消除数值距离"
- 每个类别放在**独立维度**
  - 每一维只取 0 或 1
:::

## 观测点与判别标准 {layout=cols}

::: figure src="images/roc.jpg" caption="观测点与拟合曲线" pane=0
:::

::: bullets pane=1 title="判别标准的三个后果"
- 两个分布的交叠决定判别难度
- 移动判定标准会改变**命中率和虚报率**
- 曲线越靠左上，判别越稳定
:::

# 损失函数

## 交叉熵损失 {layout=full}

::: definition
交叉熵损失用**真实类别的概率对数**衡量预测偏差，正确类别概率越低，损失越大。
:::

::: table caption="四种判断结果" placement=center firstColumnHeader=true
| 实际情况 | 判为真 | 判为假 |
|:---|:---:|:---:|
| 实际为真 | 命中 | 漏报 |
| 实际为假 | 虚警 | 正确拒绝 |
:::

# 实现与来源

## 代码与文献 {layout=full}

::: code title="交叉熵计算"
# 预测概率
p = model(x)
# 取真实类别的概率
loss = -log(p[target])
:::

:::

::: footnote
- 代码为示意，省略了批量处理和数值稳定处理。
:::
